# 로컬 Docker 앱과 시험지 첨부 계약

아래는 다음 구현 단계에서 지킬 요구사항입니다. 현재 Docker Compose, 웹·DB 서비스,
업로드 API, 추출 서비스, 백업 명령은 아직 구현하지 않았습니다.

## 실행과 데이터 보존

- 웹과 DB 모두 Docker로 실행합니다. 브라우저는 웹 서버 API를 통해 DB에 접근합니다.
- 개인용 초기 버전은 로그인 없이 사용하되 웹은 호스트 loopback에만 공개하고
  DB 포트는 호스트에 공개하지 않는 구성을 기본으로 합니다.
- DB에는 영속 볼륨을 사용합니다. 시험지 폴더는 기존 호스트 폴더를 웹에 bind mount합니다.
- 호스트 기준 폴더: `C:/00.PROJECT/PEIM/정보관리기술사_기출문제`.
  Compose는 프로젝트 상대 경로 `./정보관리기술사_기출문제`를 기준으로 구성하고,
  컨테이너 내부 경로는 환경 설정으로 주입합니다. 호스트 절대 경로를 DB에 저장하지 않습니다.
- 첨부의 DB path는 프로젝트 기준 `정보관리기술사_기출문제/{파일명}` 형식입니다.
- DB 데이터와 시험지 파일을 같은 백업 시점으로 복원할 수 있도록 함께 백업합니다.
  볼륨 존속만을 백업으로 취급하지 않습니다.

## PDF 이름과 중복 정책

- 새 PDF 이름은 `제{회차}회_정보관리기술사.pdf`입니다.
  예: 회차 140을 등록하면 `제140회_정보관리기술사.pdf`.
- 양의 정수 회차를 사용하고 기존 최대 회차를 상한으로 고정하지 않습니다.
- 업로드 파일명에서 경로를 받지 않습니다. 확인한 회차로 서버가 저장 이름을 생성합니다.
- 원래 업로드 이름은 메타데이터로만 저장합니다. 기존 자료의 원래 이름은 모르면 null입니다.
- 동일 대상 이름과 같은 해시이면 중복으로 알리고 파일을 다시 저장하지 않습니다.
- 동일 대상 이름과 다른 해시이면 충돌로 거절합니다. 자동 덮어쓰기는 금지합니다.
- 초기 버전에는 교체 기능을 제공하지 않습니다. 향후 교체는 기존 원본 버전 보관,
  DB 연결 이전, 실패 시 복구 절차를 함께 설계한 뒤 별도 추가합니다.
- 기존 HWP와 수집 기록은 유지합니다. 같은 회차 HWP가 있더라도 PDF는 별도 첨부로 연결할 수 있습니다.

## 업로드와 문항 추출 분리

1. 회차 확인과 PDF 형식·크기 검사 후 같은 파일시스템의 임시 위치로 수신합니다.
2. 파일 해시를 계산하고 중복을 검사합니다. 동시 업로드도 기존 파일을 덮어쓰지 않아야 합니다.
3. 파일 저장과 DB 첨부 기록 중 하나가 실패하면 임시 파일/미완료 레코드를 정리할 수 있도록 처리합니다.
4. 파일 등록 성공 후 추출을 별도 단계로 실행합니다. 추출 실패가 원본 파일 삭제로 이어지면 안 됩니다.
5. 추출된 문항은 초안입니다. 원문과 비교·수정하고 페이지·주제를 확인한 뒤 공개합니다.
6. 이미지형 PDF 등 추출이 어려운 경우 원본 열람과 수동 입력을 제공하며 OCR은 별도 범위입니다.

파일명 규칙과 현재 목록 검사는 data_contract.py와 build_catalog.py에서 구현했습니다.
PDF 파일의 실제 형식·손상·내용 검증과 업로드 동시성은 아직 구현하지 않았으며,
현재 목록 검사 성공을 업로드 검증 완료로 해석하지 않습니다.

## 화면 연결

- 별도의 시험지 관리 화면: 회차 추가, PDF 첨부, 처리 상태, 문항 검토.
- 학습 화면: 좌측 분야·주제/회차 탐색, 중앙 선택 문항·내 답안·저장 상태,
  우측 연결 기출·작성 상태. 주제별 참고 답안은 별도 패널.
- 문항에서 원본 시험지를 열고, 페이지가 확인된 경우 해당 페이지로 연결합니다.
- DB 저장 성공 후에만 ‘저장됨’을 표시하고, 실패 시 편집 내용을 유지합니다.
