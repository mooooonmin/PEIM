# 로컬 Docker 학습 앱

## 실행

Docker Desktop이 실행 중인 상태에서 프로젝트 폴더에서 실행합니다.

```powershell
docker compose up -d --build --wait web
```

브라우저에서 <http://localhost:8000>을 엽니다. 웹은 `127.0.0.1`에만 공개하고
PostgreSQL 포트는 호스트에 공개하지 않습니다. 로그인 없는 로컬 개인용 앱입니다.
`docker compose stop`은 서비스를 정지하고, 다시 실행해도 DB 볼륨과 시험지는 유지됩니다.
`docker compose down -v`는 DB 볼륨을 삭제하므로 데이터 보존 용도로 사용하지 마세요.

- DB: Compose의 `database` 영속 볼륨. 최초 실행 때만 정규화된 콘텐츠를 가져옵니다.
- 원본: `C:/00.PROJECT/PEIM/정보관리기술사_기출문제`를 기본값으로 사용합니다.
  Compose 상대 경로 `./정보관리기술사_기출문제`를 컨테이너 `/exams`에 연결합니다.
- DB 경로: `정보관리기술사_기출문제/{파일명}`. 호스트 절대 경로를 저장하지 않습니다.
- 환경 설정: `PEIM_PORT`(기본 8000), `PEIM_EXAM_DIR`(원본 폴더),
  `PEIM_DB_PASSWORD`(초기 DB 암호). 이미 만든 DB의 암호는 환경 변수 변경만으로 바뀌지 않습니다.
- 웹의 정적 파일·Markdown·도식 라이브러리는 이미지에 포함하며 외부 CDN이 필요하지 않습니다.

## 학습과 답안

메인 학습 화면은 왼쪽 문제·자료와 오른쪽 내 답안을 나란히 배치합니다.
상단 `문항 목록`을 펼쳐 분야·주제 또는 회차를 고르고 문항을 선택합니다.
목록의 검색은 전체 문항을 검색하며, `검색 해제`는 선택했던 주제·회차 목록으로 돌아갑니다.
검색어는 URL에 보존되고 직접 다른 문항을 선택하기 전까지 현재 답안은 유지됩니다.
상단 이전·다음 문항은 현재 목록의 검색·다시 풀기 필터와 순서를 따릅니다.

선택한 자료 탭은 파란 글씨와 밑줄로, 저장할 변경이 있는 `복습 저장`은 파란 버튼으로 구분합니다.
보조 글씨와 입력 안내의 대비를 높이고, 저장 상태는 글씨로 구분합니다.

작성 후 잠시 기다리면 DB에 자동 저장합니다. DB 성공 응답 후에만 `저장됨`을 표시합니다.
다른 문항이나 빈 회차를 불러오는 동안 추가한 답안도 저장한 뒤 이동하며, 저장 실패 시 현재 답안을 유지합니다.
작성 중/완료 상태와 문항 선택 상태는 별개입니다. 집중 모드에서는 상단 주 메뉴를 숨기고 문제·자료와 답안 공간을 넓힙니다.
저장 이력에서 최근 50개 버전을 보고 이전 내용을 새 버전으로 복원할 수 있습니다.
DB에는 더 오래된 이력도 남지만 현재 화면은 최근 50개만 조회합니다.

실패한 글은 현재 편집창과 브라우저 임시 보관에 남습니다. 저장을 재시도하거나
내 글을 내려받을 수 있습니다. 다른 창에서 먼저 저장한 경우 자동 덮어쓰기하지 않습니다.
내 글을 내려받고 서버 답안을 불러와 비교하세요. 브라우저 임시 보관은 DB 백업을 대체하지 않습니다.

## 화면 구분

- `학습`: 문제 탐색·원본/참고 답안 열람·내 답안 작성과 저장
- `문제 관리` → `기존 문항 검수`: 독립된 문항 목록·검색·회차/상태 필터와 검수
- `문제 관리` → `PDF·새 문항 등록`: 원본 첨부·추출·확인 후 새 문항 등록

주소의 `view=manage`로 문제 관리에 바로 접근할 수 있으며 `section=upload`는 등록 화면입니다.
새로고침해도 선택한 화면은 유지됩니다. 기존 문항 목록은 50개씩 표시하며 필터는 목록 전체에 적용합니다.
관리 목록의 검색어·회차·검증 상태·페이지도 URL에 보존되어 새로고침 후 이어서 볼 수 있습니다.
데스크톱에서는 열로 정렬된 목록을, 좁은 화면에서는 문항별로 묶인 목록을 표시합니다.

## 답안 비교와 복습

왼쪽 자료 탭에서 `작성 가이드 / 작성 예시 / 주제 상세 해설`을 전환하며 오른쪽 답안을 계속 작성합니다.
참고 답안은 주제별 학습 자료이며 개별 문항의 공식 정답이 아닙니다.
`보완 메모 펼치기`를 누르면 두 열 아래에서 메모와 다시 풀기를 기록할 수 있습니다.
메모를 접거나 자료를 바꿔도 입력 내용과 답안 편집기는 그대로 유지됩니다.

좁은 화면에서는 `문제·자료 / 내 답안`을 전환하며 각 본문의 읽던 위치를 유지합니다.
보완 메모는 어느 쪽에서도 펼칠 수 있습니다. 문제 제목 옆 `문제 접기/펼치기`로 자료 공간을 확보합니다.
새 문항은 문제·자료 화면과 펼쳐진 문제, 접힌 메모로 시작합니다.
1교시 문항은 1교시형 참고 자료, 다른 교시는 서술형을 먼저 선택합니다(없으면 등록된 유형 사용).

답안 자동 저장 상태는 답안 제목 아래, 복습 저장 상태는 메모 펼치기 옆에 각각 표시합니다.
복습 메모는 버튼 저장이며, 메모를 접어도 `복습: 미저장`을 확인할 수 있습니다.
자료 탭·모바일 영역 전환과 메모 접기 자체는 답안을 새로 만들거나 초기화하지 않습니다.

`보완 메모`에 빠뜨린 개념·도식·표현을 적고 `다시 풀기`를 선택한 뒤 `복습 저장`을 누릅니다.
메모와 표시는 문항별로 DB에 저장되며 답안의 작성 완료나 문항 원문 검증 상태와 별개입니다.
기출 목록에서 `이 목록에서 다시 풀 문항만`을 선택하면 현재 주제·회차·검색 결과 중 저장된 표시가 있는 문항을 봅니다.

복습 저장은 자동 저장이 아닙니다. 입력 중에는 브라우저에 임시 보관하고 문항으로 돌아올 때 복구하며 저장 실패 시 입력을 유지합니다.
문항 이동 시 미저장 메모는 임시 보관되며 복습 저장 중에는 이동을 막습니다.
다른 창과 충돌하면 `저장 문제 해결`의 `메모 내려받기`로 보관한 뒤 `서버 내용 다시 불러오기`로 최신 내용을 확인하세요.
서버 내용을 불러오기 전에는 현재 메모를 바꿀지 확인합니다. 임시 보관은 브라우저 데이터 삭제·저장 공간 부족을
견디는 백업이 아니며, 확실한 보관은 `복습 저장`으로 완료해야 합니다. DB 백업에는 복습 테이블도 포함됩니다.

## 기출문항 검수·수정

상단 `문제 관리` → `기존 문항 검수`에서 회차·문제 내용·검증 상태로 찾고 `검수·수정`을 엽니다.
학습 화면에는 편집 버튼을 두지 않습니다. 문제 관리로 이동하기 전에 내 답안의 미저장 내용을 먼저 저장하며,
답안 저장 실패 시 이동하지 않습니다. 관리 중 다른 문항을 수정해도 학습 중이던 문항은 바뀌지 않습니다. PDF.js로 그린 원본 페이지와 편집 폼을 나란히 보고 대조할 수 있습니다.
브라우저에서 PDF가 표시되지 않으면 `원본 별도 창으로 열기`를 사용하세요. HWP는 내려받아 확인합니다.
검수 창 하단의 저장 버튼과 결과 메시지는 스크롤해도 유지됩니다. 데스크톱은 원본과 편집 영역을
각각 스크롤하며, 좁은 화면에서는 `원본 / 편집 / 이력` 버튼으로 전환합니다. 전환해도 입력 내용은 유지됩니다.

검수 창의 `이전 문항 / 다음 문항`은 창을 열 때의 회차·검색·검증 상태에 맞는 전체 목록 순서로 이동합니다.
목록 페이지 경계도 이어서 이동하며, 상단에 현재 위치와 저장된 검증 상태를 표시합니다.
순서는 창을 닫을 때까지 고정됩니다. 미확인 문항을 확인 완료로 저장해 관리 목록에서 빠져도 다음 문항을
건너뛰지 않습니다. 바뀐 필터 결과로 다시 시작하려면 창을 닫고 목록에서 문항을 엽니다.

`저장 후 다음`은 저장과 화면 갱신 성공 후 다음 문항을 엽니다. 저장 실패·충돌이면 현재 입력을 유지합니다.
저장 후 다음 문항 불러오기에만 실패하면 저장 완료와 이동 실패를 구분해 안내합니다. 마지막 문항에서는
`문항 수정 저장`을 사용합니다. 저장하지 않은 수정이 있는 상태에서 일반 이전·다음 이동 시 버림 여부를 확인합니다.

PDF의 `− / +`는 너비 맞춤 기준 50~250%를 25% 단위로 조정하며, `너비 맞춤`은 100%로 돌아갑니다.
확대된 원본은 가로로 스크롤할 수 있습니다. 새 문항을 열면 너비 맞춤으로 초기화되고, 배율과 PDF 페이지 이동은
출처 페이지 입력값을 변경하지 않습니다.

- 문제 내용, 하나 이상의 연결 주제, 기존 원본별 시작·끝 페이지, 문항 검증 상태를 수정합니다.
- 회차·교시·문항 번호·ID와 원본 연결은 고정입니다. 내 답안과 답안 저장 이력은 변경하지 않습니다.
- 페이지는 PDF의 실제 파일 기준 1부터 시작합니다. 시작·끝을 함께 입력하거나 모두 비웁니다.
  페이지를 입력하면 실제 PDF 페이지 수와 등록 해시를 검사합니다. HWP 페이지 연결은 지원하지 않습니다.
- 상태는 `미확인`, `확인 완료`, `재검토 필요`입니다. 확인 완료는 원본 연결과 명시적인 대조 확인이 필요합니다.
  이는 사용자의 확인 기록이며 자동 정답 검증이 아닙니다. 페이지를 모르는 원본 연결은 미확인으로 남습니다.
- 저장은 버튼으로 명시적으로 수행합니다. 실패·다른 창과의 충돌 시 입력 내용은 현재 폼에 유지됩니다.
  충돌한 글은 복사해 보관하고 화면을 닫았다가 다시 열어 최신 문항과 비교하세요.
- 저장하지 않고 닫을 때 확인합니다. 검수 초안은 브라우저 영속 보관 대상이 아니므로 탭을 강제로
  닫거나 브라우저가 종료되면 복구되지 않을 수 있습니다.
- 하단 수정 이력에서 최근 50개 변경의 전후 내용·주제·상태·페이지와 수정 시각을 확인합니다.
  이전 값으로 자동 복원하는 기능은 제공하지 않으며, 필요한 내용을 새 수정으로 저장합니다.

이 변경은 로컬 DB에 저장하며 초기 콘텐츠 JSON이나 원본 시험지는 수정하지 않습니다.

## 새 회차 PDF와 문항 등록

1. `문제 관리` → `PDF·새 문항 등록`에서 회차와 PDF를 선택합니다. 회차는 기존 최댓값에 고정하지 않습니다.
   이미 등록된 PDF는 왼쪽 시험지 목록에서 선택합니다. PDF를 선택하면 문항 입력 폼이 나타납니다.
2. 서버는 `제{회차}회_정보관리기술사.pdf`로 저장합니다. 예: `제140회_정보관리기술사.pdf`.
   업로드한 이름은 메타데이터로만 남습니다. PDF는 최대 32 MiB, 1~500페이지이며
   암호화되었거나 파서가 읽을 수 없는 파일은 거절합니다. 파싱 성공이 내용의 정확성을 보증하지는 않습니다.
3. 같은 이름·같은 해시는 중복으로 처리하고, 다른 해시는 충돌로 거절합니다.
   동시 업로드에서도 기존 원본을 덮어쓰지 않습니다. 교체 기능은 제공하지 않습니다.
4. 등록한 시험지에서 텍스트와 문항 후보를 추출합니다. 후보는 초안이며 자동으로 학습 문항이 되지 않습니다.
5. 원본을 열어 교시·번호·문제·페이지·연결 주제를 확인합니다. 필요한 주제는 새로 만들 수 있습니다.
   확인 표시 후 문항을 등록하면 학습 화면에 나타납니다. 기존 문항 ID는 덮어쓰지 않습니다.
6. 이미지형 PDF는 OCR을 제공하지 않으므로 직접 입력합니다. 기존 HWP는 보존하고 다운로드할 수 있으나
   HWP 업로드·문항 추출·편집은 이번 구현 범위가 아닙니다.

파일은 같은 폴더의 임시 파일에서 검증한 뒤 완성된 파일을 배타적으로 게시합니다.
DB 기록 실패 시 완성된 원본이 남을 수 있으며 같은 파일을 재등록하면 기록을 복구합니다.
원본 열기·추출·새 문항 등록은 현재 파일의 SHA-256을 등록 값과 대조합니다.
외부에서 바뀐 파일은 거절하며, 새 문항의 페이지는 실제 PDF에서 확인합니다. 원본을 덮어써 복구하지 마세요.
추출 실패로 원본을 삭제하지 않습니다. 기존 원본·수집 기록·콘텐츠 파일도 유지합니다.

런타임에서 추가한 PDF는 Git 기본 제외 대상이며, 문항·첨부 정보는 DB에 저장합니다.
버전 관리되는 초기 콘텐츠 목록과 자동으로 합치지 않습니다. 자세한 경계는
[콘텐츠 파이프라인](content-pipeline.md)을 참고하세요.

## 백업과 복원

호스트 Python과 Docker CLI가 필요합니다. 별도 Python 패키지는 필요하지 않습니다.
앱을 잠시 정지한 상태에서 DB 덤프와 같은 시점의 시험지 파일을 함께 ZIP에 보관하고
각 파일의 SHA-256을 기록합니다. 직접 원본 폴더를 수정하는 작업도 백업 중에는 중지하세요.
백업 ZIP에는 내 답안과 원본이 들어가며 암호화되지 않습니다.

```powershell
python scripts/backup.py create backups/peim-backup.zip
python scripts/backup.py verify backups/peim-backup.zip
```

기존 백업 이름은 덮어쓰지 않습니다. 복원 전 현재 데이터를 다른 이름으로 백업하세요.
복원 대상 DB가 실행 중이고 시험지 폴더가 존재해야 합니다.

```powershell
docker compose up -d --wait db
python scripts/backup.py restore backups/peim-backup.zip --confirm-replace-database
docker compose up -d --wait web
```

복원은 **PEIM 전용 DB의 public 스키마를 백업 시점으로 교체**합니다.
최신 테이블의 외래 키가 이전 백업 복원을 막지 않도록 스키마 재생성과 SQL 복원을 하나의 트랜잭션으로 실행합니다.
현재 백업 이후 추가된 메모·답안도 교체 대상이므로 반드시 별도 백업을 먼저 만드세요.
다른 서비스와 공유하는 DB나 별도 스키마의 복원 도구로 사용하지 마세요.
현재 앱을 다시 시작하면 백업 시점 이후의 추가형 스키마 이행을 적용합니다. 시험지 파일은 없는 파일만 추가하고,
웹 정지가 완료된 뒤 같은 이름의 다른 원본이 있는지 검사하고 충돌하면 DB 복원 전에 거절합니다. 백업에 없는 파일은 삭제하지 않습니다.
백업·복원 명령을 동시에 실행하거나 실행 중 원본 폴더를 직접 수정하지 마세요.
DB 복원은 트랜잭션으로 수행하며 실패하면 웹을 정지한 상태로 두므로 오류를 확인한 후 다시 실행하세요.
다른 Compose 프로젝트는 `--project 이름`으로 지정합니다.
`PEIM_EXAM_DIR` 등 실행 때 사용한 환경 설정을 백업·복원에도 동일하게 적용해야 합니다.

## 전체 다시 풀기 목록

상단 **다시 풀기**에서 주제·회차와 관계없이 저장된 다시 풀기 문항을 모아 봅니다.
문항, 연결 주제, 답안 작성 상태와 보완 메모를 표시하며 최근 복습 저장 순으로 정렬합니다.
검색은 회차·문항 내용·연결 주제·보완 메모에 적용됩니다.
**이어서 풀기**는 메인 학습 화면에서 기존 답안을 열고, **전체 다시 풀기 목록으로** 돌아오면 목록을 갱신합니다.
문항을 열거나 답안을 작성하는 것만으로 표시는 해제되지 않습니다. 보완 메모에서 다시 풀기를 끄고 저장하면 목록에서 제외됩니다.
목록은 저장된 메모를 사용합니다. 임시 메모는 복습 저장 후 반영됩니다. 기존 답안과 작성 이력은 유지됩니다.

문제·자료와 내 답안의 배치, 모바일 전환과 보완 메모는 위 [답안 비교와 복습](#답안-비교와-복습)을 따릅니다.
읽던 위치는 현재 문항에서 유지되며 새 문항 선택이나 페이지 새로고침 시 초기화됩니다.
참고 주제·유형을 바꾸거나 다시 불러오면 참고 본문은 처음부터 표시합니다.

## 문항별 작성 가이드와 예시

문항 선택 후 왼쪽 `작성 가이드`를 오른쪽 내 답안과 함께 읽습니다.
`작성 가이드 / 작성 예시 / 주제 상세 해설` 탭으로 자료를 전환합니다. 기존 참고 답안의 short/long 본문은
주제 상세 해설에 그대로 제공하며, 문항별 예시로 간주하지 않습니다.

모든 문항에는 원문의 가·나·다 요구사항을 나눈 작성 틀과 자가 점검을 제공합니다.
예시가 없는 문항의 출제어·연결 주제는 검토할 후보이며 필수 키워드로 확정하지 않습니다.
편집한 작성 예시는 136회 1교시 4번(제4정규형), 140회 1교시 1번(AI 기반 BPR),
140회 2교시 1번(서버리스)에 제공합니다. 140회는 로컬에 해당 문항이 등록되어 있어야 합니다.
예시에는 목차·필수 키워드·자가 점검과 본문이 있으며 공식 정답 또는 전문가 검수 완료 자료가 아닙니다.
문항 원문이 변경되면 이전 예시는 숨기고 작성 틀로 전환합니다.

자가 점검 체크는 현재 문항을 보는 동안만 유지됩니다. 기록할 내용은 보완 메모에 저장하세요.
가이드 열기·자료 전환은 내 답안에 내용을 삽입하거나 답안·메모·이력을 변경하지 않습니다.
