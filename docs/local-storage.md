# 로컬 Docker 학습 앱

## 실행

Docker Desktop이 실행 중인 상태에서 프로젝트 폴더에서 실행합니다.

```powershell
docker compose up -d --build --wait web
```

브라우저에서 <http://localhost:8000>을 엽니다. 웹은 `127.0.0.1`에만 공개하고
PostgreSQL 포트는 호스트에 공개하지 않습니다. 로그인 없는 로컬 개인용 앱입니다.
`docker compose stop`은 서비스를 정지하고, 다시 실행해도 DB 볼륨과 시험지는 유지됩니다.
`docker compose down -v`는 DB 볼륨을 삭제하므로 데이터 보존 용도로 사용하지 마세요.

- DB: Compose의 `database` 영속 볼륨. 최초 실행 때만 정규화된 콘텐츠를 가져옵니다.
- 원본: `C:/00.PROJECT/PEIM/정보관리기술사_기출문제`를 기본값으로 사용합니다.
  Compose 상대 경로 `./정보관리기술사_기출문제`를 컨테이너 `/exams`에 연결합니다.
- DB 경로: `정보관리기술사_기출문제/{파일명}`. 호스트 절대 경로를 저장하지 않습니다.
- 환경 설정: `PEIM_PORT`(기본 8000), `PEIM_EXAM_DIR`(원본 폴더),
  `PEIM_DB_PASSWORD`(초기 DB 암호). 이미 만든 DB의 암호는 환경 변수 변경만으로 바뀌지 않습니다.
- 웹의 정적 파일·Markdown·도식 라이브러리는 이미지에 포함하며 외부 CDN이 필요하지 않습니다.

## 학습과 답안

좌측에서 분야·주제 또는 회차를 선택하고, 우측에서 문항을 선택합니다.
중앙에서는 문제, 원본 시험지, 주제 참고 답안, 내 답안을 볼 수 있습니다.
참고 답안은 주제별 학습 자료이며 개별 문항의 공식 정답이 아닙니다.

작성 후 잠시 기다리면 DB에 자동 저장합니다. DB 성공 응답 후에만 `저장됨`을 표시합니다.
작성 중/완료 상태와 문항 선택 상태는 별개입니다. 집중 모드에서는 탐색 패널을 숨깁니다.
저장 이력에서 최근 50개 버전을 보고 이전 내용을 새 버전으로 복원할 수 있습니다.
DB에는 더 오래된 이력도 남지만 현재 화면은 최근 50개만 조회합니다.

실패한 글은 현재 편집창과 브라우저 임시 보관에 남습니다. 저장을 재시도하거나
내 글을 내려받을 수 있습니다. 다른 창에서 먼저 저장한 경우 자동 덮어쓰기하지 않습니다.
내 글을 내려받고 서버 답안을 불러와 비교하세요. 브라우저 임시 보관은 DB 백업을 대체하지 않습니다.

## 새 회차 PDF와 문항 등록

1. `시험지 관리`에서 회차와 PDF를 선택합니다. 회차는 기존 최댓값에 고정하지 않습니다.
2. 서버는 `제{회차}회_정보관리기술사.pdf`로 저장합니다. 예: `제140회_정보관리기술사.pdf`.
   업로드한 이름은 메타데이터로만 남습니다. PDF는 최대 32 MiB, 1~500페이지이며
   암호화되었거나 파서가 읽을 수 없는 파일은 거절합니다. 파싱 성공이 내용의 정확성을 보증하지는 않습니다.
3. 같은 이름·같은 해시는 중복으로 처리하고, 다른 해시는 충돌로 거절합니다.
   동시 업로드에서도 기존 원본을 덮어쓰지 않습니다. 교체 기능은 제공하지 않습니다.
4. 등록한 시험지에서 텍스트와 문항 후보를 추출합니다. 후보는 초안이며 자동으로 학습 문항이 되지 않습니다.
5. 원본을 열어 교시·번호·문제·페이지·연결 주제를 확인합니다. 필요한 주제는 새로 만들 수 있습니다.
   확인 표시 후 문항을 등록하면 학습 화면에 나타납니다. 기존 문항 ID는 덮어쓰지 않습니다.
6. 이미지형 PDF는 OCR을 제공하지 않으므로 직접 입력합니다. 기존 HWP는 보존하고 다운로드할 수 있으나
   HWP 업로드·문항 추출·편집은 이번 구현 범위가 아닙니다.

파일은 같은 폴더의 임시 파일에서 검증한 뒤 완성된 파일을 배타적으로 게시합니다.
DB 기록 실패 시 완성된 원본이 남을 수 있으며 같은 파일을 재등록하면 기록을 복구합니다.
추출 실패로 원본을 삭제하지 않습니다. 기존 원본·수집 기록·콘텐츠 파일도 유지합니다.

런타임에서 추가한 PDF는 Git 기본 제외 대상이며, 문항·첨부 정보는 DB에 저장합니다.
버전 관리되는 초기 콘텐츠 목록과 자동으로 합치지 않습니다. 자세한 경계는
[콘텐츠 파이프라인](content-pipeline.md)을 참고하세요.

## 백업과 복원

호스트 Python과 Docker CLI가 필요합니다. 별도 Python 패키지는 필요하지 않습니다.
앱을 잠시 정지한 상태에서 DB 덤프와 같은 시점의 시험지 파일을 함께 ZIP에 보관하고
각 파일의 SHA-256을 기록합니다. 직접 원본 폴더를 수정하는 작업도 백업 중에는 중지하세요.
백업 ZIP에는 내 답안과 원본이 들어가며 암호화되지 않습니다.

```powershell
python scripts/backup.py create backups/peim-backup.zip
python scripts/backup.py verify backups/peim-backup.zip
```

기존 백업 이름은 덮어쓰지 않습니다. 복원 전 현재 데이터를 다른 이름으로 백업하세요.
복원 대상 DB가 실행 중이고 시험지 폴더가 존재해야 합니다.

```powershell
docker compose up -d --wait db
python scripts/backup.py restore backups/peim-backup.zip --confirm-replace-database
docker compose up -d --wait web
```

복원은 **DB 내용을 백업 시점으로 교체**합니다. 시험지 파일은 없는 파일만 추가하고,
같은 이름의 다른 원본이 있으면 거절합니다. 백업에 없는 파일은 삭제하지 않습니다.
DB 복원은 트랜잭션으로 수행하며 실패하면 웹을 정지한 상태로 두므로 오류를 확인한 후 다시 실행하세요.
다른 Compose 프로젝트는 `--project 이름`으로 지정합니다.
`PEIM_EXAM_DIR` 등 실행 때 사용한 환경 설정을 백업·복원에도 동일하게 적용해야 합니다.
