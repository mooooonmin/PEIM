# 개발 검사와 빌드

모든 명령은 프로젝트 루트에서 실행합니다. 작업별 결과는 커밋과 PR에 기록합니다.
검사 통과는 학습 콘텐츠의 학술적 정확성이나 원문 대조 완료를 뜻하지 않습니다.
이전 앱 구현의 검증 기록은 [PR #5](https://github.com/mooooonmin/PEIM/pull/5)에 남아 있습니다.

## 데이터 검사와 내보내기

호스트 Python 3.11 이상이 필요하며 아래 명령에는 외부 Python 패키지가 필요하지 않습니다.

```powershell
python scripts/validate_data.py
python scripts/build_catalog.py --check
python -m unittest discover -s tests -v
python scripts/check_rebuild.py
python scripts/export_dataset.py
```

원본을 수정하지 않고 관계·원본 해시·식별자·답안 범위와 재생성 일치를 검사합니다.
`check_rebuild.py`는 임시 복사본을 사용합니다. 내보내기는 Git에서 제외된
`scripts/out/dataset-v1.json`을 생성합니다. 생성 순서·검사 범위와 실제 데이터 갱신은
[콘텐츠 파이프라인](content-pipeline.md)을 참고하세요.

호스트 unittest는 데이터·백업 검사를 실행하고 앱 통합 검사는 건너뜁니다.
앱 테스트는 아래 Docker 명령으로 실행해야 합니다.

## 앱 통합 검사

Docker Desktop의 Linux 컨테이너 엔진을 실행한 상태에서 사용합니다.

```powershell
docker compose config --quiet
docker compose --profile test run --build --rm test
```

별도 `peim_test` PostgreSQL과 임시 시험지 폴더를 사용합니다. 실제 답안 DB와 원본 폴더를
사용하지 않습니다. API 저장·충돌·이력, PDF 등록·추출·문항 등록을 검사합니다.
문항 검수의 ID·답안·이력 보존, 동시 수정 충돌, 페이지 검증과 DB 추가형 이행도 검사합니다.
웹 실행 방법과 데이터 보존은 [운영 안내](local-storage.md)에서 확인합니다.

## 프런트엔드 빌드

Node.js와 npm이 필요합니다. Docker 빌드의 Node 버전 기준은 [Dockerfile](../Dockerfile)입니다.

```powershell
npm ci
npm test
npm run build
```

출력은 Git에서 제외된 `app/static/assets/`입니다. Docker 웹 이미지 빌드에도 이 과정이 포함됩니다.
`npm test`는 실제 검수·관리 핸들러를 Happy DOM과 모의 API에서 실행합니다. 필터 목록 전체 전달,
이동 경계, 미저장 수정 취소, 저장 충돌·갱신 실패·이동 실패, 중복 저장 방지, 저장 후 다음 이동과 배율을 검사합니다.
모의 API 검사는 실제 PostgreSQL 통합 검사나 브라우저 PDF 렌더링 검사를 대신하지 않습니다.
메인 비교·복습 핸들러 검사는 편집기와 복습 영역의 메인 배치, 문항 이동 시 임시 메모 복구, 메모·표시 저장, 충돌 시 임시 메모 유지, 문항 간 격리,
참고 자료 응답 순서, 빈 자료와 로딩 실패를 확인합니다. DB 통합 검사는 v3 추가형 이행과 재시작 후 메모 유지,
기존 답안·이력 보존, 메모 동시 저장 충돌과 입력 검증을 포함합니다.
화면 동작 변경 시 브라우저에서 해당 흐름과 저장 상태를 확인하고 PR에 범위·결과를 기록합니다.
학습·문제 관리 전환은 미저장 답안 저장, 관리에서 다른 문항 수정 후 학습 문항 유지,
목록 검색·상태 필터·페이지 이동, PDF 등록 화면과 새로고침 후 화면 유지를 확인합니다.
학습 검색은 결과 제목·건수·검색 해제 후 기존 주제 목록 복원을, 관리 검색은 회차·상태·검색어·페이지의
URL 복원을 확인합니다. 검수 창은 데스크톱의 독립 스크롤과 고정 저장 영역, 모바일의 원본·편집·이력 전환을
확인합니다. 실제 사용자 문항·답안에 테스트 값을 저장하지 않으며 저장 회귀 검사는 격리된 통합 테스트로 수행합니다.
연속 검수는 필터 순서·현재 위치·첫/끝 경계·모바일 저장 버튼 노출·PDF 확대/축소/너비 맞춤을 확인합니다.

## 문서 변경과 PR 검사

문서만 바꿀 때는 변경한 설명을 실제 코드·경로와 대조하고 상대 링크와 아래 검사를 확인합니다.
동작 변경이 없으면 앱 통합 검사를 로컬에서 다시 실행할 필요는 없으며 미실행 이유를 기록합니다.

```powershell
git diff --check
```

PR에서는 [데이터 검사](../.github/workflows/data-checks.yml)와
[앱 검사](../.github/workflows/app-checks.yml)가 실행됩니다.
CI 실행 여부와 보호 규칙의 필수 검사 등록은 서로 다릅니다. 실제 결과를 확인한 뒤 병합합니다.

2열 학습 화면 검사는 같은 답안 편집기·선택 범위·메모 유지, 문항 목록·메모 접기,
새 문항의 읽던 위치 초기화, 필터 순서의 이전·다음 이동과 중복 클릭·이동 취소를 확인합니다.
브라우저에서는 왼쪽 문제·자료와 오른쪽 답안 배치, 모바일 영역 전환과 가로 넘침을 확인합니다.

전체 다시 풀기 목록 검사는 서로 다른 회차의 문항·메모 조회, 프로필 격리, 표시 해제와 기존 답안·이력 보존을 포함합니다.
`tests/retry-list.test.mjs`는 검색, 메모의 안전한 텍스트 출력, 이어서 풀기, 빈 목록과 요청 실패 시 재시도를 확인합니다.
브라우저에서는 전체 목록에서 메인 학습 화면으로 이동한 뒤 목록으로 돌아오는 흐름과 모바일 배치를 확인합니다.

비교 레이아웃 회귀 검사는 답안·참고 본문의 개별 스크롤 위치 복원, 같은 메모 폼 공유, 문항 이동 시 위치 초기화를 포함합니다.
브라우저에서는 모바일 문제·자료/내 답안 전환과 메모 펼치기·접기, 참고 자료를 읽은 위치 유지 여부를 확인합니다.


문항별 가이드 검사는 원문 하위 항목 분리, 예시의 문항 일치·수정 후 숨김, 미등록 상태,
API 읽기 전용과 기존 참고 답안·개인 답안·이력 보존을 포함합니다.
`tests/writing-guide.test.mjs`는 자료 전환·스크롤·자가 점검 유지, 문항 간 응답 격리,
안전한 출력, 요청 실패와 재시도를 검사합니다. 브라우저에서는 작성 가이드 진입,
작성 예시 탭, 주제 상세 해설 전환, 모바일 문제·자료/내 답안 전환을 확인합니다.
